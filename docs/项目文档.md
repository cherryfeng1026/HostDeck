# HostDeck 项目文档

## 1. 项目定位

HostDeck 是一个面向个人或小团队场景的轻量级 Linux 运维面板，目标是用尽量简单的部署方式提供以下能力：

- 服务器资产管理
- SSH 连通性测试
- 资源状态采集与总览
- 单机详情与趋势查看
- 远程命令执行
- 基础告警规则与告警列表

当前项目采用 Go 后端单进程托管前端静态资源的方式运行，适合单机部署和小规模服务器管理场景。

## 2. 当前能力

### 2.1 服务器管理

- 新增、编辑、删除服务器
- 配置主机名、IP、SSH 端口、用户名、标签、用途和备注
- 支持立即执行 SSH 连通性测试
- 支持立即执行一次服务器采集

### 2.2 SSH 凭据安全

- 服务器密码在后端加密存储
- 页面创建或编辑时可写入密码，但不会回显已保存密码
- 读接口仅返回 `passwordConfigured` 状态，不返回明文凭据
- `master_key` 未正确配置时，系统会拒绝保存服务器密码

### 2.3 状态采集与展示

- 默认按周期采集服务器状态
- 支持总览页查看在线、离线、SSH 异常等统计
- 支持详情页查看系统版本、内核版本、CPU、内存、磁盘、负载和趋势数据

### 2.4 运维操作

- 支持单条 Linux 命令远程执行
- 返回 `stdout`、`stderr`、退出码和耗时
- 保留命令日志

### 2.5 告警能力

- 支持基础规则配置
- 支持查看当前告警和规则列表

### 2.6 登录鉴权与权限控制

- 支持用户名密码登录、登出、当前用户查询、用户列表查询与修改密码
- 使用 HttpOnly 会话 Cookie 维护登录状态
- 支持 `admin`、`operator`、`viewer` 三种角色
- 提供独立用户管理页，支持个人改密与管理员只读查看用户列表
- `viewer` 可查看总览、服务器、告警和活动信息
- `admin` 与 `operator` 可执行采集、SSH 测试、命令执行、服务器维护与告警规则修改
- 支持通过启动配置显式创建初始管理员，或通过 bootstrap token 初始化管理员
- 若数据库内无任何账号且未显式配置 bootstrap 管理员，系统保持未初始化状态，登录接口返回明确的未初始化语义
- 登录页会根据 `/api/auth/status` 展示未初始化提示，不再依赖默认弱口令管理员

### 2.7 控制台壳层能力

- 顶栏显示当前用户、角色、通知数量与最近活动
- 支持通知列表、活动流与全局搜索
- 提供统一品牌图标与 favicon

## 3. 技术架构

### 3.1 后端

- Go 1.25
- `chi` 作为 HTTP Router
- `database/sql` 访问数据库
- 当前推荐使用 PostgreSQL / Neon
- SSH 连接使用 `golang.org/x/crypto/ssh`

### 3.2 前端

- Vue 3
- TypeScript
- Vite
- Naive UI
- ECharts

### 3.3 运行模式

开发时：

- 后端独立运行
- 前端修改后需要重新执行构建

发布时：

- 前端构建产物输出到 `web/dist/`
- 后端直接托管 `web/dist/`
- 日常运行只需启动 Go 后端

## 5. 快速启动

### 5.1 前置条件

- Go 已安装并可用
- Node.js / npm 已安装并可用
- 已准备 PostgreSQL / Neon 数据库
- 已准备 `server/config/config.yaml`

如果配置文件不存在，先执行：

```powershell
Copy-Item .\server\config\config.example.yaml .\server\config\config.yaml
```

至少确认以下配置项：

- `db_dsn`: PostgreSQL / Neon 连接串
- `master_key`: 必须替换 `change-me`
- `session_cookie_name`: 会话 Cookie 名称
- `session_ttl_hours`: 会话有效期
- `bootstrap_admin_username` / `bootstrap_admin_password`: 可选，启动时显式创建管理员
- `bootstrap_admin_token`: 可选，启用初始化接口时使用
- 若两者都未配置且库内无任何用户，系统会保持未初始化状态，需先完成初始化后再登录

### 5.2 首次启动或前端改动后

```powershell
Set-Location .\web
npm install
npm run build
Set-Location ..\server
go run .\cmd\hostdeck --config .\config\config.yaml
```

### 5.3 日常启动

如果前端代码没有改动，只需要启动后端：

```powershell
Set-Location .\server
go run .\cmd\hostdeck --config .\config\config.yaml
```

### 5.4 启动验证

```powershell
Invoke-WebRequest http://127.0.0.1:18080/api/healthz
```

预期返回：

```json
{"ok":true,"version":"0.1.0"}
```

页面地址：

```text
http://127.0.0.1:18080/
```

首次访问业务页会根据登录状态自动跳转到 `/login` 或控制台首页。

## 6. 部署建议

当前推荐部署方式：

- 一个 HostDeck 后端进程
- 一个外部 PostgreSQL / Neon 数据库
- 前端静态资源由后端托管
- 用 systemd、supervisor、pm2 或 Windows 服务托管进程

### 6.1 构建

前端构建：

```powershell
Set-Location .\web
npm install
npm run build
```

后端构建：

```powershell
Set-Location ..\server
go build -o .\bin\hostdeck.exe .\cmd\hostdeck
```

也可以直接使用仓库脚本：

```powershell
Set-Location .\server
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

### 6.2 运行

```powershell
Set-Location .\server
.\bin\hostdeck.exe --config .\config\config.yaml
```

### 6.3 生产环境建议

- 使用独立的 PostgreSQL / Neon
- 为 `master_key` 使用高强度随机字符串
- 通过反向代理处理 HTTPS
- 定期备份数据库

### 6.4 Docker 方向

当前仓库没有现成 Dockerfile。如果后续要容器化，建议采用：

```text
反向代理 -> HostDeck 容器 -> PostgreSQL / Neon
```

不建议把数据库和应用强绑定在同一容器里。

## 7. 常见问题

### 7.1 为什么只启动 Go 后端就能打开页面？

因为前端在构建后会输出到 `web/dist/`，后端会直接托管这些静态资源。

### 7.2 为什么编辑服务器时看不到旧密码？

这是刻意的安全策略。系统不会回显已保存的密码；如果不需要修改密码，留空保存即可。

### 7.3 为什么必须配置 `master_key`？

因为 SSH 密码需要在后端加密保存。如果仍然使用默认值，系统会拒绝保存密码。
