# HostDeck 任务清单

## 1. 文档目的

本文档用于沉淀 HostDeck 下一阶段的完整实施任务，覆盖 P0 / P1 / P2 三个优先级层级，供开发排期、拆解执行和验收使用。

任务设计遵循以下原则：

- 先修正控制面的可信度与安全性，再扩展效率型能力
- 先落实已经暴露给用户但尚未真正生效的语义，再新增更重的能力
- 优先保持项目“个人 / 小团队轻量 Linux 运维面板”的产品定位，不提前引入企业级重平台复杂度

---

## 2. 总体执行顺序

建议按以下顺序推进：

1. **P0：控制面可信化**
   - 修正监控采集正确性
   - 告警状态化
   - 安全基线补齐
2. **P1：高频效率增强**
   - 命令中心升级
   - 用户管理闭环
   - 通知能力落地
   - 文件操作与排障链路增强
3. **P2：平台化与扩展能力**
   - Agent / Hybrid Collector
   - 容器管理
   - 开放集成层
   - 更细粒度治理能力

这样可以避免在监控数据不可信、告警无状态、安全基线不足的情况下继续叠加能力，导致后续返工。

---

## 3. 里程碑规划

### Milestone A：监控可信

目标：让总览、详情、趋势、列表中的状态数据真实可用。

完成标准：

- CPU 使用率不再恒为 0
- 禁用服务器不再继续参与采集和操作
- 轮询并发度由配置真实控制
- 采集模式文案与实际能力一致

### Milestone B：告警可用

目标：让告警从“页面展示阈值结果”升级为“具有生命周期的可用告警系统”。

完成标准：

- 告警触发、恢复、确认、静默具备持久化语义
- `durationSeconds` 真正参与判定
- 当前告警与历史告警可区分展示
- 活动流可显示告警关键事件

### Milestone C：控制面安全达标

目标：让 HostDeck 可以作为正式控制面使用，而不是仅适用于非常宽松的测试环境。

完成标准：

- 去掉默认弱口令管理员自动创建
- 初始管理员引导改为显式初始化流程
- SSH host key 校验落地
- 敏感操作具备最小审计能力

### Milestone D：高频运维效率提升

目标：提升个人 / 小团队的日常使用频率与留存价值。

完成标准：

- 命令模板、历史、收藏可用
- 用户管理闭环完成
- 至少一种通知通道可用
- 文件编辑 / 深度排障链路显著增强

---

## 4. P0 任务清单：控制面可信化

## P0-1 监控采集正确性

### 目标

- CPU 使用率真实可用
- `enabled` 字段真正控制采集与操作行为
- `pollConcurrency` 配置真实生效
- `collectorMode` 在 Agent 未实现前不再误导用户

### 当前问题

- CPU 当前固定写为 `0`
- 调度侧对配置语义落地不足
- 前端暴露了 `prefer_agent` / `agent_only`，但后端未真正实现相关行为

### 后端任务

#### 任务 1：实现真实 CPU 采集

**涉及文件**

- `server/internal/collector/ssh_collector.go`
- 需要时新增 CPU 解析辅助文件

**实施内容**

- 基于 `/proc/stat` 实现 CPU 使用率采样
- 选择双采样计算方案，或在轮询架构允许范围内实现可靠近似值
- 明确 CPU 百分比的定义，避免与 load average 混用
- 若短期内无法稳定实现双采样，先将 UI 与 API 语义调整为真实可解释的数据，不保留伪 CPU 指标

**验收标准**

- Dashboard、Server Detail、趋势图中的 CPU 指标随负载变化
- 压测或命令制造负载后，CPU 指标能明显上升
- CPU 告警规则有实际判定价值

#### 任务 2：让 `enabled` 真正生效

**涉及文件**

- `server/internal/scheduler/poller.go`
- `server/internal/api/probe_handler.go`
- `server/internal/api/command_handler.go`
- 相关 SSH 测试 handler / service
- 服务器查询与展示相关 service

**实施内容**

- 调度器跳过 `enabled = false` 的服务器
- 手动 probe、测试 SSH、执行命令时校验服务器是否启用
- 为停用状态返回明确错误信息
- 保持读接口可查看停用服务器，但状态展示为停用而不是“异常在线状态”

**验收标准**

- 停用服务器不再参与周期采集
- 停用服务器无法执行运维动作
- 前端列表和详情可见明确停用状态

#### 任务 3：让 `pollConcurrency` 生效

**涉及文件**

- `server/internal/scheduler/poller.go`
- `server/cmd/hostdeck/main.go`
- `server/internal/config/config.go`

**实施内容**

- 引入 worker pool 或 semaphore 控制轮询并发
- 单台机器采集失败不阻断整轮采集
- 轮询日志中体现并发行为，便于排查
- 配置错误时使用合理默认值并记录日志

**验收标准**

- 修改并发配置后，整轮采集耗时有可观变化
- 高延迟 SSH 主机不会拖垮全部轮询流程
- 轮询在小规模和中等规模机器下行为稳定

#### 任务 4：收口 `collectorMode`

**涉及文件**

- `server/internal/domain/*`
- `server/internal/api/server_handler.go`
- `server/internal/storage/server_repository.go`
- `web/src/components/ServerModal.vue`

**实施内容**

- 若短期不落地 Agent，后端统一把采集模式收口为 `ssh_only`
- 前端移除或禁用 `prefer_agent` / `agent_only`
- 若需要保留字段兼容未来扩展，应在 UI 上明确标注“暂未启用”

**验收标准**

- 用户不会误以为 Agent 已经可用
- 接口返回值与 UI 行为一致
- 数据库中不会继续沉淀无意义模式值

### 前端任务

#### 任务 5：校正采集相关 UI

**涉及文件**

- `web/src/pages/DashboardPage.vue`
- `web/src/pages/ServersPage.vue`
- `web/src/pages/ServerDetailPage.vue`
- `web/src/components/ServerModal.vue`
- `web/src/components/ServerStatusTable.vue`

**实施内容**

- 统一展示停用状态
- 禁用服务器的动作按钮置灰
- 调整采集模式文案
- 若 CPU 指标语义变化，则同步修改图表文案和 tooltip

**验收标准**

- 用户能直观看到服务器停用态
- UI 中不存在与后端能力不一致的入口

### 测试任务

#### 任务 6：补采集与调度测试

**涉及文件**

- collector 相关测试
- poller 相关测试
- API 测试

**实施内容**

- 增加 CPU 解析测试
- 增加 disabled 节点跳过测试
- 增加 poll concurrency 行为测试
- 增加停用服务器禁止操作的接口测试

**验收标准**

- 关键采集逻辑与边界条件均有自动化测试覆盖

## P0-2 告警状态化

### 目标

让告警从“读取时临时计算的结果”升级为“具有触发、恢复、确认、静默、历史的告警系统”。

### 当前问题

- 告警缺少状态机
- `durationSeconds` 没有真正落地
- 活动流、通知、搜索无法复用标准告警事件
- 页面上有规则管理，但缺少完整运维语义

### 后端任务

#### 任务 7：重构告警判定时机

**涉及文件**

- `server/internal/service/alert_service.go`
- 状态落库与采集完成后的处理流
- 相关 repository

**实施内容**

- 将规则判定从 `GET /api/alerts` 的读时计算改为写时评估
- 在每次状态采集成功后触发告警判定
- 读接口只负责读取当前告警和历史告警

**验收标准**

- 告警不再依赖用户访问页面才“出现”
- API 返回当前真实状态，而非临时拼装结果

#### 任务 8：落地 `durationSeconds`

**涉及文件**

- `server/internal/service/alert_service.go`
- 告警状态持久化层

**实施内容**

- 为规则-服务器维度记录首次越阈时间
- 达到持续时间后才转入 active
- 越阈中断后重置计时

**验收标准**

- 短时抖动不会立即形成正式告警
- 满足持续时长后才进入当前告警列表

#### 任务 9：加入恢复、确认、静默能力

**涉及文件**

- `server/internal/api/alert_handler.go`
- `server/internal/service/alert_service.go`
- 告警 repository / migration

**实施内容**

- 实现自动恢复
- 实现手动确认（ack）
- 实现静默（按实例或规则最小可用版本）
- 为每次状态变化记录事件

**建议接口**

- `POST /api/alerts/{id}/ack`
- `POST /api/alerts/{id}/mute`
- `GET /api/alert-history`

**验收标准**

- 当前告警与历史告警可区分
- 告警恢复后从当前告警中移除并进入历史
- 确认和静默动作具备明确状态反馈

#### 任务 10：让活动流与搜索接入告警事件

**涉及文件**

- `server/internal/service/shell_service.go`
- 搜索与活动流 repository

**实施内容**

- 活动流增加告警触发、恢复、确认、静默事件
- 搜索支持检索近期关键告警事件
- 与后续通知系统共用事件源

**验收标准**

- 活动流不再只包含命令与认证事件
- 用户能通过搜索定位关键告警变化

### 数据库任务

#### 任务 11：新增告警状态与历史表

**涉及文件**

- `server/internal/storage/migrate.go`
- 新增告警 repository 文件

**建议表结构**

- `active_alerts`
- `alert_events` 或 `alert_history`

**字段建议**

- `server_id`
- `rule_id`
- `status`
- `first_triggered_at`
- `triggered_at`
- `resolved_at`
- `acked_at`
- `muted_until`
- `message`
- `snapshot`

**验收标准**

- 数据模型能完整表达告警生命周期
- migration 支持平滑升级

### 前端任务

#### 任务 12：重构告警页面

**涉及文件**

- `web/src/pages/AlertPage.vue`
- 可能新增告警列表组件 / 历史列表组件

**实施内容**

- 页面分为“当前活动告警”和“历史事件”两部分
- 新增确认、静默入口
- 展示触发时间、持续时间、恢复时间、状态标签
- 优化规则管理区与当前告警区的关系，避免混杂

**验收标准**

- 告警页面能完整表达当前状态与历史变化
- 用户操作后页面反馈即时明确

### 测试任务

#### 任务 13：补告警状态机测试

**实施内容**

- 增加规则判定单测
- 增加持续时间边界测试
- 增加恢复 / 确认 / 静默测试
- 增加 API 测试与前端状态展示测试

**验收标准**

- 告警主要生命周期路径均有测试覆盖

## P0-3 安全基线补齐

### 目标

- 去掉默认弱口令管理员
- 初始引导流程显式化
- 引入 SSH host key 校验
- 补充最小敏感操作审计

### 后端任务

#### 任务 14：取消默认管理员自动创建

**涉及文件**

- `server/internal/service/auth_service.go`
- `server/internal/api/auth_handler.go`
- `README.md`
- `docs/项目文档.md`

**实施内容**

- 去除数据库为空时自动创建 `admin/admin123` 的逻辑
- 若配置 bootstrap 用户名 / 密码，则允许初始化
- 若配置 bootstrap token，则允许通过初始化接口创建管理员
- 若系统未初始化，则返回明确的“未初始化”状态

**验收标准**

- 不存在默认弱口令可直接登录的路径
- 初始化流程明确、单一、可理解

#### 任务 15：引入 SSH host key 指纹校验

**涉及文件**

- `server/internal/sshx/client.go`
- `server/internal/service/server_connection_service.go`
- 服务器 domain / storage / API
- `web/src/components/ServerModal.vue`
- 服务器详情 / 测试 SSH 交互页面

**实施内容**

- 每台服务器记录 `host_key_fingerprint`
- 首次 SSH 测试时获取实际指纹
- 提供“信任并保存”动作
- 后续连接强制校验指纹一致性
- 指纹变更时拒绝连接并提示人工确认

**验收标准**

- 首次连接可完成指纹登记
- 指纹不匹配时连接被阻断
- 用户可重新信任新指纹

#### 任务 16：补最小敏感操作审计

**涉及文件**

- 命令执行 service / repository
- 服务器修改相关 handler / service
- 规则修改相关 handler / service
- 认证事件相关模块

**实施内容**

- 记录谁执行了命令
- 记录谁修改了服务器信息
- 记录谁修改了告警规则
- 记录谁完成了初始化管理员动作

**验收标准**

- 敏感控制面行为可追溯
- 活动流与后续审计具备统一事件来源

### 前端任务

#### 任务 17：初始化与 SSH 指纹交互完善

**涉及文件**

- `web/src/pages/LoginPage.vue`
- `web/src/components/ServerModal.vue`
- 服务器相关页面

**实施内容**

- 登录页支持“系统未初始化”态展示
- 引导管理员初始化
- 测试 SSH 时展示指纹校验流程
- 为风险操作提供清晰提示

**验收标准**

- 首次使用流程对用户可理解
- SSH 信任建立流程可操作

### 测试任务

#### 任务 18：补认证与 SSH 安全测试

**实施内容**

- 未初始化状态测试
- bootstrap 流程测试
- host key 正常 / 变更 / 异常测试
- 敏感操作审计事件测试

**验收标准**

- 安全相关关键路径均有自动化覆盖
